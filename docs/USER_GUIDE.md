# ACE - Simple Car Tuner: user guide

How to install and use the tuner step by step, with all the details. The short overview is in the [README](README.md).

Change the driving settings of a car in a simple table, install your own tuned copy next to the stock one, drive a lap, close the game, change again. About 136-142 settings per car: engine, turbo, gearbox and clutch, differential (setup and hardware), steering, brakes, springs, dampers, anti-roll bars, ride height and bump stops, alignment, tyres, driver aids, fuel. No cosmetics.

The selector lists all 71 cars of the game. A tuned copy of a car is a **modded car** (steps 3 and 4 of "Every time you tune"). The stock cars are never changed.

## What you need

- Windows PC with **Assetto Corsa EVO** and the **Assetto Corsa EVO SDK** installed through Steam (both fully downloaded).
- **Python 3.9 or newer** from python.org (the start files find it through the `py` launcher, on `PATH`, or in the usual install folders `%LOCALAPPDATA%\Programs\Python\Python3*\` and `%ProgramFiles%\Python3*\`; to use a particular one, set the `PY` line in `start_tuner.bat` and `start_logger.bat` to the full path of its `python.exe`).
- This repository (clone or download it).

## One-time setup

1. Open a terminal in the repository folder and extract the car data field names from the SDK (they belong to the game vendor, so they stay on your PC and are not part of this repository):
   ```
   python tools\extract_protos.py "C:\Program Files (x86)\Steam\steamapps\common\Assetto Corsa EVO SDK\AssettoCorsaEVOEditor.exe" schemas
   ```
   If the file holds no descriptors the command stops with an error and writes nothing: use `AssettoCorsaEVOEditor.exe` from the SDK. Without the SDK the game's own `AssettoCorsaEVO.exe` (in `...\steamapps\common\Assetto Corsa EVO\`) works too: it lacks only a few editor-only descriptors, the car data descriptors are the same (checked on game 0.9.1).
2. Double-click **`start_tuner.bat`** in the repository root (the top folder, next to `docs`, `tools` and `tuner`). A console window opens and your browser shows the tuner (dark theme) at http://127.0.0.1:8090/ACESCT/ . The console also prints the address for other devices in your home network, for example `http://192.168.1.20:8090/ACESCT/`: open that on your phone or tablet (same Wi-Fi). The first time, Windows asks whether Python may use the private network: choose **Allow**. Only devices in your home network (addresses like 192.168.x.x or 10.x.x.x) are let in, there is no password, so use it on a network you trust. On an iPhone open the address in Safari, tap Share and **Add to Home Screen**: the page then starts like an app with its own icon (a rev counter). Keep the console window open while you use it. (After updating the repository, close that window and start it again.)
3. Pick a car in the selector at the top. Its groups, top to bottom, are **Modded Cars** (entries like `BMW M3 E46 CSL MY - installed`), **Installed Cars** (the car's game files were pulled) and **Other Cars** (not pulled yet). The first time you pick a car from Other Cars, press **Install car (pull game files)** (about 20 seconds). This copies that car's data and its shared tyre files out of the game into `%USERPROFILE%\ace_modded_cars_work\<car id>`. Every car of the game is installed the same way: select it in the list and press **Install car (pull game files)**. Some cars have further presets with their own physics (for example the Toyota Supra MKIV's Drift preset): once the car is installed, they appear right below it in **Installed Cars** as `<car> - <preset> (preset, view only)`. Selecting one shows that preset's values (engine, turbos, gearbox, differential, setup) read-only, so you can copy the ones you like by hand into your own modded car; nothing can be changed or built from it. The same on the command line: `python tools	une.py variants --car <car id>` and `python tools	une.py defaults --car <car id> --variant <preset id>`.

## Every time you tune

1. Close the game (the tuner refuses to install while it runs).
2. Choose an installed car (starts from the stock values) or a modded car (loads its saved values), then change values in the table. The settings are in categories (Meta, Display, Engine, ...) that are all collapsed when a car is loaded: click a category, or use **Expand all** / **Collapse all**; an open category shows a short description under its name. Each row shows: variable name, your value, the car's default (right next to your value), and a description. The small "+" buttons above the table add a column with the lowest and highest value of one car category (Front RWD modern, GT3, Drift ...; hover over a button for its cars, over a value for the exact numbers), "−" hides it again; the columns are only a guide, you can enter what you like. The very first time the buttons appear after a few seconds. Changed rows are highlighted blue and have a **reset** button. Use the search box, or tick **changed only** to see what you changed; both open the categories that match while they are set. The spring collar positions are hidden unless you tick **show advanced settings** (Kunos says the editor's Auto Setup computes them; a changed one stays listed). Settings a car does not have (for example turbo values on a naturally aspirated car, unless you chose a turbo kit for it) are hidden; the line under the title tells you how many.
3. With an installed car selected, press **Create modded car…**. A panel proposes the tuned car id (same length as the stock id; the first one is `ax_<stock>`, further ones a counter id such as `ax_bmw_m3_e46_c01`) and the car name; edit them if you like and confirm. The name of the modded car is the stock name plus the car name (proposed `MY`, then `MY 2`, `MY 3`), so it sorts right next to the stock car in the game's car list; you can make several modded cars of one stock car, each with its own saved values, suffix and package in the mods folder. After a few seconds the green message tells you the new package was installed, the draft is emptied and the new car is selected under Modded Cars. Create never overwrites an existing modded car.
4. To rework it later, pick the car under **Modded Cars**, change values and press **Apply (update this car)**; this updates exactly that car. Press **Duplicate…** to copy a modded car to a new one (the panel proposes id and suffix; leave them empty for automatic ones).
   When the build is finished the green message lists what changed since the last build of this car: the changed settings (old -> new) and the changes of the turbo kit, the tyres offered in the game and the borrowed sounds. The first build of a car lists everything compared with the stock car; if nothing changed it says so. The build log below it (collapsed) shows the same lines.
5. Start the game, open Vehicle Selection, pick your modded car (for example `BMW M3 E46 CSL MY`, next to the stock one), drive.
6. Close the game and repeat.

Own tyres (optional, not verified in the game yet):

- The page has two tabs, **Car Tuner** (everything above) and **Tyre Creator**, which builds own tyres. A tyre has a name (the game shows it), a short name of 1 to 3 letters, a source (any tyre of the game) and the values you changed against that source. There are 109 settings in 11 groups (**Expand all**, **Collapse all**, search). The small "+" buttons above the table add a column with the lowest and highest value of one tyre type (Road, Supercar, Racing slick ...; hover for the exact values), as a guide how far to go; "−" hides it again; the columns only show values, you can enter what you like. The size is not a setting: choose another source tyre. Most effects are only assumed from the field names and not tested in the game. A tyre is single: use it four times or on one axle only. Kunos advises against changing the tyre model values (the tab shows a warning): change little and test in the game. Use **New tyre…**, **Rename…**, **Delete**, the **Source** selector and **Reset all values**. Tyres are saved in `%USERPROFILE%\ace_modded_cars_work\tyres` and shared by all cars; a tyre edit reaches a car at its next Apply or Create. Delete is refused while a modded car or draft has the tyre ticked.
- The panel **Tyres offered in the game** (Car Tuner tab, at the bottom below the settings table, closed at the start) decides which tyres the modded car offers in the game (Fuel & strategy lets you pick the front and rear tyre separately). Tick tyre sets: the original sets of the car, your own tyres and every tyre of the game (grouped by type, sorted by size, with search); tyres in the car's own size are listed first, the others are marked as another size. With the checkbox **Different front and rear tyres** you pick the front and the rear list separately. **Starts on** is what the car begins with. At least one tyre stays ticked per axle; nothing stored means the original tyres and the car is not touched, **Reset to the original tyres** goes back to that. The choice is saved per version and used by Apply and Create.

Adding a turbo to a car without one (optional, not verified in the game yet): a modded car whose stock car has no turbo can get the turbo setup of a donor, any installed car that has a turbo. This only adds a turbo to a car that has none: there is no supercharger and nothing for electric cars.

1. Select the modded car, or an installed car (its draft), that has no turbo.
2. Open the panel **Turbo kit** below the settings table (above **Tyres offered in the game**, closed at the start). It is not shown for a car that has a turbo itself. If it says that no installed car has a turbo, install one first: select a car with a turbo and press **Install car (pull game files)**.
3. Under **Turbo from** choose the donor. Each entry reads `<name> - single turbo, 0.9 bar` (or twin turbo, or the number of turbos; one boost value per turbo, for example `0.7 / 0.9 bar`). `~1.2 bar (reference)` means the turbo files carry no boost and only the engine's reference value is known; no bar means the game data has no boost value for that car. The line below says which turbo you got, for example "Chosen: twin turbo (2 turbos), boost 0.7 / 0.7 bar, from <name>". The choice is saved per modded car and draft, and Duplicate and Create copy it. **No turbo kit (stock engine)** takes it away again.
4. The table now has the category **Turbo** (Turbo 1 max boost, Turbo 2 max boost for a twin turbo, Engine max boost) with the donor's values as defaults. Change them like any other setting. A turbo multiplies the engine power on top of the power curve, so lower the boost if the car becomes too strong.
5. Press **Create modded car…** or **Apply (update this car)** as usual. The build log of the result (collapsed) lists the "turbo kit" notes: the donor, the turbo files and the engine fields that were copied.
6. Start the game and try the car. If it does not load or drives wrongly, choose **No turbo kit (stock engine)** and Apply again, or remove the modded car (see "Remove a modded car" below).

Nobody has tried a turbo kit in the game yet: whether the game accepts a turbo on a car that had none and whether a twin turbo needs more than the copied settings are open. The sound of the turbo is chosen in the **Sounds** panel (next section); choosing a donor sets the turbo sound to the donor's by default.

Borrowing sounds from other cars (optional, not heard in the game yet): the panel **Sounds** (below **Tyres offered in the game**, closed at the start) lets a modded car use the turbo sound (the whistle, probably with the blow-off valve) and the exhaust backfire sound of any other installed car.
1. Open **Sounds**. The two lists **Turbo sound** and **Backfire sound** contain every sound used by your installed cars, each with the cars that use it, for example `turbo_rx7 - Mazda RX-7 FD Spirit R`. The first entry is the car's own sound. Install more cars to get more sounds in the lists.
2. Pick a sound. It is saved at once for this car or draft; **Reset to the car's own sounds** removes your choices.
3. Press **Create modded car…** or **Apply (update this car)**. The build log lists the change, for example `sound turbo: turbo_none -> turbo_rx7`. Only the turbo and backfire sound change; the engine sound, the power and the handling stay as they are.
4. If a chosen sound disappears (its car was removed from the work folder) Apply refuses until you change or reset it.

### Versions of a modded car (several setups in one car)

A modded car can carry several complete setups as **versions**. In the game you pick the car and then its version, like the game's own Toyota Supra MKIV with its Drift version.

1. Select your modded car in the selector. Next to it a **Version** list appears: **Base** is the car's own setup.
2. Press **Add version…** to make a new version: type a name (it is shown in the game as the version's name, at most 40 characters) and confirm: the new version starts as a copy of the version you were looking at and is selected.
3. Change the values of the version as usual. Most settings can differ per version (power, turbo, gears, differential, clutch, brakes, springs, anti-roll bars, dampers, camber, ride height, steer ratio, tyres, sounds). Shared by all versions and changed only on **Base**: the names, weight, force feedback, steering speed (`steer_rod_ratio`), steering lock, the body stiffness of the anti-roll bars and "driver aids off", because the game takes them from the Base once you paint a version. A version keeps its own setup when you paint it in the game; cars painted before 2026-11-23 19:41 do not, paint them again. If you remove a version, do not select its painted cars in the game any more: the game may crash.
4. Press **Apply**: one package with all versions is built and installed. Start the game and choose the version in the car selection. The menu shows each version under the name you gave it; Base is called "Base"; you can give it another name with **Rename version…** while Base is selected. If Apply says a version "would not show in the game", nothing was built or installed.
5. **Rename version…** renames the selected version, or Base when Base is selected. The page never deletes anything: the line **Where it lives** shows the installed package and the versions folder; to remove a version, delete its folder there by hand, then press Apply.
6. **Lock version** freezes a version you are happy with. Apply builds all versions every time (the game needs them in one package), but a locked version is not rebuilt: Apply puts exactly the files of the build you drove back into the package, so later changes of the base, a new tuner version or a game update cannot change them (the settings shared by all versions, such as weight and force feedback, still follow the Base). A locked version shows "(locked)" in the list and cannot be edited or renamed. You can only lock a version after an Apply that included its latest changes (otherwise the page says "Apply first, then lock it"). **Unlock version** makes it editable again; the next Apply builds it again. To experiment from a locked version, select it and use **Add version…**: the copy is not locked. The Base cannot be locked.

The Apply summary lists every version: how many settings changed since its last build, or "locked, not rebuilt".

"unverified" next to a description means the meaning is guessed from the setting's name and not yet confirmed in the game. A "copies differ in stock" badge means the game's own files disagree about that value; applying writes your value to every copy. Every setting is explained in its row of the table. Where a setting has an entry in the official physics documentation of the game (https://docs.assetto.cn/en/evo/car/physics/), its description starts with the official statement and continues with our notes; the rules learned from it are in [docs/TUNER_SPEC.md](TUNER_SPEC.md) section 6c.

## Log what the game does (optional, not tried with the game yet)

The session logger records what the game really does with your settings, so that you (or an AI) can check afterwards that your changes arrived and how the car's behaviour changed. It has nothing to do with lap times or driving lines.

1. Open the tab **Logging**. At the top are **Behaviour values** (speed, rpm, steering, g-forces, wheel loads, slip, suspension travel, tyre and brake temperatures; only Speed, Engine rpm, Throttle and Brake are ticked at the start) and **Car state** (tyre compound names, turbo level, damper levels and more; nothing ticked), then the tuner groups. The tab is one table like the Tuner tab: one header (tick, Setting, Unit, Once = read once per session, Live = read in every sample) that stays visible while you scroll, and each group is a row with a chevron that opens its rows; the group checkbox in the tick column ticks all its rows. A setting the game shows directly (camber, ride height, tyre pressure, brake bias, boost, rev limit, diff levels, steering lock, fuel, driver aids and a few more) has a checkbox. Settings the game cannot show (springs, dampers, toe, caster, gear ratios, tyre model) have no checkbox: they are dimmed and say "effect only" (judged through the Behaviour values) or "not published". Groups without any tickable row are at the bottom. A channel that several ticked rows share is logged once. Choose the sample rate (30 or 60 Hz). Your choices are saved at once and apply from the next session. **Reset to default** deletes your saved choice and goes back to the standard set of the repository: Speed, Engine rpm, Throttle and Brake at 30 Hz (the standard comes from `tuner/log_channels.json`, so it is the same for everyone; "Tick all" and "Clear all" change only your saved choice).
2. Press **Start logger** on the page (a hidden background program starts; **Stop logger** ends it) or double-click **`start_logger.bat`** (repository root) and leave its window open. Then start the game. The status line shows "Logger: waiting for the game", then "logging <file>".
3. Drive. One file per session is written to the `logs` folder of the repository (the car, the track or the session changing, or closing the game, ends a file). Nothing is written while the game is paused.
4. Give the file (or two files, from before and after a change) to an AI. In **Recent sessions**, press **Copy AI command** once and paste it into a new chat with an AI (ChatGPT, Claude or another): it explains the game, the mod program, what the logs are for, the values with their units and limits, which rows exist, how to answer, and that the AI should say when it is unsure. Then press **Copy file** in the row of a session and paste (Ctrl+V) the file into the same chat; on the PC the file itself is copied and attached, from a phone or another PC its text is copied (up to 1 MB). A file is JSON Lines: the first line has the car, the track, the PC time, the game and logger version, the logger's choices and all the tuner facts (every value of the car with its default, the tyres offered in the game, the turbo kit, the sounds, when the car was last built and installed, what changed in that build, and when the game started); then one line with the once-only values (read when the car stands still), then the samples, and a last line with the end reason.

Stop the logger with the page's **Stop logger** button (or Ctrl+C in its window) when you are done. The files are not part of the repository (the folder `logs` is ignored by git). With the default four rows a session file grows by about 9 MB per hour at 30 Hz (18 MB at 60 Hz); with all Behaviour values ticked it is about 75 MB per hour at 30 Hz (145 MB at 60 Hz). If the repository lies in a synced folder (OneDrive, Dropbox), start the logger with `--logs <folder outside it>`.

## Good to know


- **Check a power change without driving:** when a session starts the game writes a line like `POWER CLASS INDEX ... (357.19 HP)` into the newest file in `%USERPROFILE%\Saved Games\ACE\Logs`.
- **Undo:** every install keeps a backup of the previous package in `%USERPROFILE%\ace_modded_cars_work\backups`. Copy one over the file in `%USERPROFILE%\Saved Games\ACE\mods\`, or delete the tuned car's `.kspkg` there to remove it completely.
- **Remove a modded car:** the page has no delete button. Delete its folder `%USERPROFILE%\ace_modded_cars_work\<stock car id>\tunes\<id>`, the file `%USERPROFILE%\ace_modded_cars_work\<stock car id>\snapshots\<id>.json` (the record of its last build) and its `<id>.kspkg` in the mods folder by hand. The first modded car `ax_<stock>` keeps its files in `<stock car id>\tune_state.json` and `<stock car id>\build\<id>` instead.
- **Your values** are remembered in `%USERPROFILE%\ace_modded_cars_work\<stock car id>`: the draft of an installed car in `draft_state.json`, each modded car in `tunes\<id>\tune_state.json` (the first one, `ax_<stock>`, in `tune_state.json` next to the draft). **Reset all** clears the values of the selected car or draft, including its tyre choice and its turbo kit.
- **Turbo kit folders:** for each turbo kit the tuner builds a copy of the car with the donor's turbo in `%USERPROFILE%\ace_modded_cars_work\<stock car id>\kit\<donor id>` (files are hard links where the disk allows it) and rebuilds it by itself when the car's or the donor's files change. It never deletes one: after removing a kit or a modded car, delete that folder by hand if you do not need it.
- **Car not in the list in the game?** Check that its `ax_....kspkg` is directly inside `%USERPROFILE%\Saved Games\ACE\mods\`, and look at the newest game log for errors.
- **Python not found?** Install Python 3.9 or newer from python.org, or set the `PY` line in `start_tuner.bat` (repository root) to the full path of `python.exe`.
- **Port 8090 taken by another program?** Change the `PORT` line in `start_tuner.bat`.
- **"game package not found"?** The tuner looks for the game's `content.kspkg` in the default Steam folder (`C:\Program Files (x86)\Steam\steamapps\common\Assetto Corsa EVO\content.kspkg`). If the game is in another Steam library, put the full path of `content.kspkg` into the `GAME` line of `start_tuner.bat` (or pass `--game <path>` to `tools\tune.py cars` / `init` and to `tools\tuner_server.py`).
- Command-line use: `python tools\tune.py cars [--modded] | init --car <id> | defaults --car <id> | show | set <id> <value> | unset <id> | apply | duplicate` (every command except `cars` takes `--car <id>`). Tyres: `tyres | tyre-index [--type <type>] | tyre-new --name <text> --source <game path or name> [--short <XX>] | tyre-show <id> | tyre-set <id> <setting> <value> | tyre-unset <id> <setting> | tyre-delete <id>` (no `--car`; `tyre-index` prints the game's tyres) and `tyres-convert --name <text> [--version <id>]` (makes own tyres of a car's old tyre values); tyres offered in the game: `garage | garage-set <file> | garage-reset`, each with `[--tune <id> | --draft] [--car <id>]` (`<file>` is a JSON file with the choice); turbo kit: `turbo-donors [--car <id>] | turbo-add <donor> | turbo-remove | turbo-kit` (the last three with `[--tune <id> | --draft] [--car <id>]`; `turbo-kit` builds the kit and prints what it copied); sounds: `sounds | sound-set <slot> <key> | sound-reset [<slot>]` (each with `[--tune <id> | --draft] [--car <id>]`). `cars --modded` lists the modded cars; `show`, `set`, `unset`, `defaults` and `apply` take `--tune <id>` to work on one modded car; `duplicate [--tune <id> | --draft] [--new-id <id>] [--suffix <text>]` copies a modded car or the draft to a new modded car.
  `apply` refuses to install while the game is running (`--no-install` only builds and is not refused). An install first writes `<name>.kspkg.part` into the mods folder and replaces the package atomically when the copy is complete, so a failed copy leaves the old package intact.
- **Do not close the console window while a job runs** (install a car or apply): Ctrl+C waits for the running job, a second Ctrl+C aborts it. Edits are refused while a job runs.
- Server options: `python tools\tuner_server.py [--port N] [--bind <address>] [--work <dir>] [--mods <dir>] [--logs <dir>] [--game <content.kspkg>]`; `--bind 127.0.0.1` serves this PC only (the default is all network interfaces); `--game` points at the game's `content.kspkg` when it is not in the default Steam folder, `--logs` is the folder of the session files (default `logs` in the repository). The logger takes `python tools\logger.py [--work <dir>] [--mods <dir>] [--logs <dir>]`; `python tools\ace_shm.py dump` prints one frame of the game's shared memory while the game runs.
- All tools print their usage block on stdout and exit with code 2 when called with wrong or missing arguments; runtime errors are `error: ...` on stderr with exit code 1.
- Tests: `python -m unittest discover -s tests` runs the test suite (about 30 seconds); it needs no game data and runs in the cloud as well. One file: `python -m unittest discover -s tests -p test_garage.py`; one test class: `cd tests` and then `python -m unittest test_garage.TestStateKey`.
