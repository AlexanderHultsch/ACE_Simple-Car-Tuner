## 5. Key knowledge

- **Loading mod cars:** one `.kspkg` directly in `%USERPROFILE%\Saved Games\ACE\mods\`. A mod car needs `content\cars\<id>\<id>.moddedcarcontent` (ModdedCarContentData: display name, brand, year, property_1/2/3 = classes) and its names in `content\cars\<id>\uiresources\localization\en.cars.loc` (CRLF, UTF-8, no BOM; copied from the game's stock `en.cars.loc` lines of that car with the new id); without it the selection screen shows raw keys. Cars need no patching of the game's own package. Single player only.
- **Mods are read at game start only (tested 2026-11-14):** while the game runs it keeps `ax_*.kspkg` open without delete sharing (rename, replace and write fail), and a new package in the mods folder is not listed until the game is restarted (not after the main menu, not after the garage). So a car cannot be changed live; close the game, Apply, start the game. Details: TUNER_SPEC section 4g.
- **Stock registration data:** the game's `system\cars.table` (TableData -> preset.lines[].car_content, CarContentData) has name, display_name, brand, year, properties for each of the 71 cars; the tool stores them in `stock_info.json` per car. A missing property means the enum default (Road / Modern / ICE).
- **All cars listed:** the selector shows all 71 game cars (names from `cars.table`, cached in `<work>\cars_index.json`); `tuner/cars.json` is only the list of TESTED cars (five). Untested cars (six tried: F40 LM, Audi Sport Quattro, Alpine A290 (electric), Dallara EXP, MX-5 NA, 992 GT3 RS) extract, resolve and build without errors; loading and driving unknown; the electric car still shows combustion settings.
- **Variants vs cars (researched):** a game car has variants (mechanical presets: body parts and display specs, no physics) and trim levels (visual presets). Physics belongs to the whole car; the game's way to give variants different physics is tuning parts (`TuningPart`, referenced by a variant's forced parts). So the tuned car is its own mod car (stock car's package must not change). The user decided against saving tunes as variants; tunes stay separate copy cars.
- **Modded cars:** a modded car = stock car + own tuned-car id (same length as the stock id; the first takes `ax_<stock>`, further ones a counter id such as `ax_bmw_m3_e46_c01`) + own saved values + own name suffix (unique per stock car; proposals `_MY`, `_MY2`, `_MY3`). Layout: `<work>\<stock id>\draft_state.json` (state of the base car page, emptied after a successful Create), `<work>\<stock id>\tunes\<id>\{tune_state.json, meta.json}`; the default tune `ax_<stock>` keeps the legacy files `<work>\<stock id>\tune_state.json` and `build\<id>`. Rules: Create builds a NEW modded car and never overwrites; Apply updates exactly the selected car; Duplicate copies a modded car or the draft; the page cannot delete (remove `tunes\<id>` and `<id>.kspkg` by hand). In the game: stock brand, name = stock display name + suffix, every modded car its own package. Server: `tune` parameter on the car-bound routes, `POST /api/duplicate`, `/api/apply` body `{car, tune, new_id?, suffix?}`; CLI: `tune.py cars --modded`, `duplicate`, `--tune <id>` (details: `tools/tune.py` and `tools/tuner_server.py` docstrings, TUNER_SPEC section 4c).
- **Clone trick:** the id is replaced everywhere by a same-length id (`ks_` -> `ax_`), so no protobuf length prefix changes. The id appears inside `.mesh`, `.actor`, `.car` and others. All 71 game car ids start with `ks_`.
- **Car manifest:** each car's `.car` (CarData; file name varies: `<id>.car`, `cardata.car`, `<id>_car.car`) has `engine_path`, `drivetrain_path`, `gearbox_path`, `clutch_path`, `brakes_path`, `stock_setup`, `setupLimits` (mixed-case paths) and embeds inline copies of engine, gearbox, drivetrain, brakes. The catalogue uses these as roles (`@engine`, `@gearbox`, `@setup`, `@limits`, `@car`, `@mech_preset`, `@turbo[N]`). Which copy the game reads is unknown; the tuner writes both. Some stock copies differ (RX-7).
- **`.kspkg`:** 64 MiB file table at the end, XOR key `c135117da921979f`, 256-byte entries (path, flags 1 = directory / 0x100 = data XOR'd, FNV-1a 64 hash of the lower-case path as UTF-16LE, size, offset); the game's `content.kspkg` (66 GB) uses the same format, all files XOR-flagged; our `pack` variant (flags 0, lower-case paths) is accepted by the game. Windows paths over 260 characters occur (Porsche thumbnails): kspkg/clone/tune use extended-length paths.
- **Schemas:** the SDK Editor exe (and the game exe) embed the protobuf descriptors; `tools/extract_protos.py` writes them to `schemas/`. Real game files also contain "legacy tail" fields beyond the schema (second gear set in `.drivetrain`, foreign car names): preserved in `_unknown`. Unmapped `car_json` types: `.actor`, `.cardisplaysystem`, `.carwipersystem`, `.tyremesh`. `.tyre` (TyresCompoundData) is mapped; tyre files are shared under `content\cars\common_phsx` and are extracted into `<base>\content\cars\common_phsx` by `init` / lazily; a changed tyre becomes the car's own file under `data\tyres\`.
- **Catalogue mechanics** (`tuner/catalogue.json`, see `tune.py` docstring): the top-level `groups` list (name, description, display order; every setting's group is listed and every listed group is used) and the optional setting flag `advanced` (a hint for the page only); targets name a role and a dotted JSON path (`[n]` index, `[key=VALUE]` selector); `optional` targets (inline `.car` copies) are written only when present; `needs` guards applicability; `hide_if_absent`; `default_template` for the variant name (`{stock_variant_name}`); `[*]` wildcard in paths (all elements), `create_missing` (absent intermediate objects are created on write), kind `flag` (bool that writes a fixed value, e.g. `driver_aids_off`), `choice_values` (enum choice name to written text, e.g. thermal curve families), roles `@clutch`, `@coilover_front/@coilover_rear`, `@tyre_front/@tyre_rear`; a setting is applicable when its required targets resolve; unknown ids in a saved state are ignored with a warning.
- **Verify power/mass without driving:** the newest `Saved Games\ACE\Logs\log-*.txt` has `Creating car: <id>` and `POWER CLASS INDEX: ... (357.18982 HP) W:1517.65` at session start. Unchanged clone and stock match exactly (BMW).
- **Tyres:** `.tyre` files (TyresCompoundData) are shared; a changed axle gets the car's own `data\tyres\<new id>_front/_rear.tyre`, and the `.car` (`frontTyreCompounds/rearTyreCompounds`) plus the `compatibletyres` entry of the stock-default compound are rewired to it. Only the starting compound changes; the garage's other compounds stay stock as long as the car has no garage selection (key `_tyres`, TUNER_SPEC 4d). Thermal curve is a choice setting (curve families, e.g. supercar). 24 tyre settings in total, 12 per axle.
- **Check an install without driving:** after `tune.py apply` compare installed vs built hash, run `car_json.py check`, confirm the registration display name and that no package path contains the stock id (done for the BMW before the first install).
