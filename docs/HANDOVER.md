## 2. The project in short

A local table page to tune Assetto Corsa EVO cars for drifting: read a car's data with real field names, change values, build an own copy of the car under an `ax_` id (a **modded car**, shown in the game as the stock name plus a user-chosen suffix, setting `name_suffix`), install it in the game's mods folder, drive, repeat. Driving settings only, no cosmetics. All 71 game cars are listed and installed on Alex's PC; five are tested against the real game files: BMW M3 E46 CSL, Toyota GR86, Mazda RX-7 FD, Alfa Romeo Giulia GTAm, Porsche 992 GT3 R Rennsport (list in `tuner/cars.json`). 143 settings in the catalogue, 136-142 applicable per tested car. **Nothing has been driven yet:** the development laptop (Intel UHD 128 MB) crashes in the renderer for every car, so only the selection screen and the game log can be used there; everything about driving waits for the gaming PC.

What exists (details in TUNER_SPEC): the table page (collapsible categories, defaults, "Range for base cars", descriptions based on the official Kunos documentation); modded cars (Create, Apply, Duplicate, saved per car) next to the stock cars; the Tyre Creator tab and the per-car Garage tyres panel; the Turbo kit (give a car without a turbo the turbo of a donor); the Sound picker (turbo and backfire sound of any installed car); the Session logger (`start_logger.bat`, tab "Logging": the game's shared memory as JSON Lines per session for an AI; built 2026-11-16, never run against the game); the page on the home network at `/ACESCT/` (port 8080, private networks only, no PIN) with an iPhone home-screen icon. In the game only the BMW's display values were ever seen.

## 4. Working rules

- Process: Claude plans and reviews; subagents write all code under the user's "executor contract" (stock general-purpose subagent, model haiku for mechanical one or two file jobs, sonnet where judgment is needed; the contract text is copied verbatim into every delegation; it is in `docs/working-contract.md`). One step at a time; the parent runs the verification itself and reads the diff; never accept a green run reached by weakening a test. Show a plan and wait for the user's OK before building, unless the user asks to run uninterrupted. Docs and git are done by the planner directly.
- Tests: `python -m unittest discover -s tests` (stdlib, no game data) must stay green. **On the local PC the suite assumes no game and no `schemas/`:** with `schemas/` present about 27 tests fail because they find the real game and field names; rename `schemas/` away for the run (`Rename-Item schemas schemas_hold`, rename it back afterwards) or run in a clean checkout. Even then `test_unknown_car_is_an_error_line_on_stderr_with_exit_1` fails on a PC with the game installed (`tune.py` creates the work folder while reading the game's car list); this is a known, accepted environment dependency (owner decision 2026-11-13: document, no environment variable for the game path).
- Vendor data stays out of git: `schemas/`, the work folder, `*.kspkg`, game and SDK files. Third-party mods are not kept in the repo: we build our own program (decision of Alex, 2026-11-13).
- Test with scratch folders (`--work <short dir>`, `--mods <dir>`); never touch the real work folder's state, the real mods folder, the game folder, the SDK folder or the stock cars while testing. The game may be running: the tuner refuses to install then. Always back up before replacing a package (the tools do).
- Edit car data only through `tools/car_json.py` (lossless). A setting changes every copy of a value.
- Do not use `Nenkai/ACEvo.Package` (its AGENTS.md prohibits use by AI tools).
- Do not publish tuned derivatives of Kunos' cars. Credit: Kunos Simulazioni (game and data). The repo holds tools, the settings catalogue and docs; no game assets or packages.

## 6. Key knowledge

- **Loading mod cars:** one `.kspkg` directly in `%USERPROFILE%\Saved Games\ACE\mods\`. A mod car needs `content\cars\<id>\<id>.moddedcarcontent` (ModdedCarContentData: display name, brand, year, property_1/2/3 = classes) and its names in `content\cars\<id>\uiresources\localization\en.cars.loc` (CRLF, UTF-8, no BOM; copied from the game's stock `en.cars.loc` lines of that car with the new id); without it the selection screen shows raw keys. Cars need no patching of the game's own package. Single player only.
- **Mods are read at game start only (tested 2026-11-14):** while the game runs it keeps `ax_*.kspkg` open without delete sharing (rename, replace and write fail), and a new package in the mods folder is not listed until the game is restarted. So a car cannot be changed live; close the game, Apply, start the game (TUNER_SPEC section 4g).
- **Stock registration data:** the game's `system\cars.table` (TableData -> preset.lines[].car_content, CarContentData) has name, display_name, brand, year, properties for each of the 71 cars; the tool stores them in `stock_info.json` per car. A missing property means the enum default (Road / Modern / ICE).
- **All cars listed:** the selector shows all 71 game cars (names from `cars.table`, cached in `<work>\cars_index.json`); `tuner/cars.json` is only the list of TESTED cars (five). The other cars extract, resolve and build without errors; loading and driving unknown; the electric car (Alpine A290) still shows combustion settings.
- **Variants vs cars (researched):** a game car has variants (mechanical presets: body parts and display specs, no physics) and trim levels (visual presets). Physics belongs to the whole car; the game's way to give variants different physics is tuning parts (`TuningPart`). So the tuned car is its own mod car (the stock car's package must not change). Alex decided against saving tunes as variants.
- **Modded cars:** a modded car = stock car + own tuned-car id (same length as the stock id; the first takes `ax_<stock>`, further ones a counter id such as `ax_bmw_m3_e46_c01`) + own saved values + own name suffix (unique per stock car). Layout: `<work>\<stock id>\draft_state.json` (state of the base car page, emptied after a successful Create), `<work>\<stock id>\tunes\<id>\{tune_state.json, meta.json}`; the default tune `ax_<stock>` keeps the legacy files `<work>\<stock id>\tune_state.json` and `build\<id>`. Rules: Create builds a NEW modded car and never overwrites; Apply updates exactly the selected car; Duplicate copies a modded car or the draft; the page cannot delete (remove `tunes\<id>` and `<id>.kspkg` by hand). Server: `tune` parameter on the car-bound routes, `POST /api/duplicate`, `/api/apply` body `{car, tune, new_id?, suffix?}`; CLI: `tune.py cars --modded`, `duplicate`, `--tune <id>` (TUNER_SPEC section 4c).
- **Clone trick:** the id is replaced everywhere by a same-length id (`ks_` -> `ax_`), so no protobuf length prefix changes. Exception: an id directly after `event:/evo_cars/` or `content\sfx\` (or `content/sfx/`) is kept, because it names the game's own sound events and bank (`content\sfx\<id>.bank` in the game package; the engine sound of modded cars depended on this, fixed 2026-11-14, rebuild old packages with Apply). The id appears inside `.mesh`, `.actor`, `.car` and others. All 71 game car ids start with `ks_`. Known oddity, not fixed: the stock `.actor` of the VW Golf R MK8 names a file in the GTI MK8 folder with the R's id in its name; the clone renames that file name, so only that car is affected.
- **Car manifest:** each car's `.car` (CarData; file name varies: `<id>.car`, `cardata.car`, `<id>_car.car`) has `engine_path`, `drivetrain_path`, `gearbox_path`, `clutch_path`, `brakes_path`, `stock_setup`, `setupLimits` (mixed-case paths) and embeds inline copies of engine, gearbox, drivetrain, brakes. The catalogue uses these as roles (`@engine`, `@gearbox`, `@setup`, `@limits`, `@car`, `@mech_preset`, `@turbo[N]`). Which copy the game reads is unknown; the tuner writes both. Some stock copies differ (RX-7).
- **`.kspkg`:** 64 MiB file table at the end, XOR key `c135117da921979f`, 256-byte entries (path, flags 1 = directory / 0x100 = data XOR'd, FNV-1a 64 hash of the lower-case path as UTF-16LE, size, offset); the game's `content.kspkg` (66 GB) uses the same format, all files XOR-flagged; our `pack` variant (flags 0, lower-case paths) is accepted by the game. Windows paths over 260 characters occur (Porsche thumbnails): kspkg/clone/tune use extended-length paths.
- **Schemas:** the SDK Editor exe (and the game exe) embed the protobuf descriptors; `tools/extract_protos.py` writes them to `schemas/` (`acevo.desc` is the only file read at runtime; the `.proto` files are readable documentation of the field names). Real game files also contain "legacy tail" fields beyond the schema (second gear set in `.drivetrain`, foreign car names): preserved in `_unknown`. Unmapped `car_json` types: `.cardisplaysystem`, `.carwipersystem`, `.tyremesh`. `.actor` is mapped as `ActorData` (root message; the car is its field 103 `CarActorData`). `.tyre` (TyresCompoundData) is mapped; tyre files are shared under `content\cars\common_phsx` and are extracted into `<base>\content\cars\common_phsx` by `init` / lazily; a changed tyre becomes the car's own file under `data\tyres\`.
- **Catalogue mechanics** (`tuner/catalogue.json`, see `tune.py` docstring): the top-level `groups` list (name, description, display order; every setting's group is listed and every listed group is used) and the optional setting flag `advanced` (a hint for the page only); targets name a role and a dotted JSON path (`[n]` index, `[key=VALUE]` selector); `optional` targets (inline `.car` copies) are written only when present; `needs` guards applicability; `hide_if_absent`; `default_template` for the variant name; `[*]` wildcard in paths, `create_missing`, kind `flag` (bool that writes a fixed value, e.g. `driver_aids_off`), `choice_values` (enum choice name to written text, e.g. thermal curve families), roles `@clutch`, `@coilover_front/@coilover_rear`, `@tyre_front/@tyre_rear`; a setting is applicable when its required targets resolve; unknown ids in a saved state are ignored with a warning (the keys `_tyres`, `_turbo`, `_sounds` are not settings).
- **Verify power/mass without driving:** the newest `Saved Games\ACE\Logs\log-*.txt` has `Creating car: <id>` and `POWER CLASS INDEX: ... (357.18982 HP) W:1517.65` at session start.
- **Tyres:** `.tyre` files are shared; a changed axle gets the car's own `data\tyres\<new id>_front/_rear.tyre`, and the `.car` plus the `compatibletyres` entry of the stock-default compound are rewired to it. The garage selection (`_tyres`, TUNER_SPEC 4d) decides which tyres a modded car offers. 24 tyre settings, 12 per axle.
- **Sound:** the car banks are in the game's global `content\sfx\` (one `<car id>.bank` per car plus shared banks); the car links its sounds in its `.actor` (`audio_events`); turbo and backfire are separate entries of type `TurboEvent` / `Backfire` using the shared `turbo.bank` / `backfire.bank` (the blow-off valve samples are inside the turbo bank). Details: CONCEPT_TURBO_SOUND.md section 9, TUNER_SPEC 4i.
- **Check an install without driving:** after `tune.py apply` compare installed vs built hash, run `car_json.py check` and `refgraph.py` on the build, confirm the registration display name and that no package path contains the stock id.

Known limits:
- The ranges in `ranges.json` show what the game stores: some mix units (`brake_bias_hw` percent and fraction) or are wide (`gear_1` up to 13.97 on one car); they are not recommendations. `ranges.json` is not refreshed by the page (`tune.py ranges`).
- There is no PIN on the network page: anyone in the home network can change the car settings (Alex accepted this); the router may give the PC another `192.168.x.x` address after a restart (the server prints the current ones at start).
- "Reset all" of a modded car or draft also drops its garage, turbo kit and sound choices; a modded car other than the default one keeps only its name suffix.
- The tyre calls of the Tyre Creator carry the Car Tuner selection (`car`/`tune`): a stale modded-car selection can make them answer 400 until the Car Tuner refresh falls back to the draft.
- Failed garage, turbo kit or sound loads show their message inside the collapsed panel, which is invisible while the panel is closed. A saved garage or sound choice that is no longer valid makes Apply and Create refuse until it is changed or reset. Own tyres can only be deleted when no modded car and no draft ticks them.
- After resetting a changed advanced row while "show advanced settings" is off the row disappears and the keyboard focus drops to the page; the "N hidden" count includes the advanced rows of collapsed groups; `aria-describedby` of a group button points at its description, which is hidden while the group is closed.
- Decided limits of the Modded Cars feature (not bugs): at most 99 counter ids per stock car (`..01` .. `..99`); suffixes are unique per stock car and compared exactly (case-sensitive); the Duplicate dialog cannot prefill the suffix (the server picks it when the field is empty); after a failed Create the page does not select the half-created car; the first modded car of a stock car takes the default id only through Create/Apply (a Duplicate proposes the counter id); the page never deletes anything.
- Turbo kit (TUNER_SPEC section 4h; nothing about it is tested on real data or in the game): kit folders are never deleted, also not after `turbo-remove` or after deleting the modded car: delete `<work>\<car>\kit\<donor>` by hand; the kit does not notice shared tyre files that are extracted into `base` later: delete `kit\<donor>` after such a change; a kit rebuild while another request reads the old tree can give that request a transient error; the `.car` file's inline engine block is patched only when both cars have one; a failed `GET /api/turbo` hides the whole panel; long option texts of the donor select are clipped at 375 px; `turbo-donors --car` shows the choice of the default tune only; the extra turbo settings of section 9 (lag up / down, wastegate, controllers) will also apply to cars with a kit once they are in the catalogue.
- Sound picker (TUNER_SPEC section 4i): the options exist only for installed cars; no audio preview; a car with two entries of one type would change only the first (none exists).
- Session logger (TUNER_SPEC section 4j, CONCEPT_LOGGER.md): built and tested on synthetic memory and one end-to-end run against fake named blocks, never against the real game. The game publishes no setup values: only 29 settings are tickable; the others are greyed (decision of Alex; the declined ideas of CONCEPT_LOGGER section 8b stay out unless he asks). The game closing is detected after 5 s, so `duration_s` of such a session includes the wait; the header's tuner facts call `tune.effective_rows`, which may read the game package once if a car's files are missing in the work folder; a damaged `tuner/log_channels.json` stops the logger at the next session start with an `error:` line; the tab has no lock between two quick saves; `logs/` is inside OneDrive (git-ignored). Catch-up samples after a pause shorter than 1 s can arrive in a short burst. Added 2026-11-16: the page's Start and Stop buttons spawn and stop the logger (anyone on the home network can press them; the hidden process writes `logs/logger_console.log`; a killed logger leaves its status file behind, the page then shows "not running" after 5 s); "Copy file" needs a secure browser context for the clipboard API (on plain http at a 192.168.x.x address the page uses a hidden text field instead); the server copies a file to the clipboard only for loopback clients; `tuner/log_ai_command.txt` and `tuner/log_glossary.json` are what the AI reads (the glossary's unit and caveat statements are not verified in the game); the 413 hint of the page matches the server's message text.

## 9. Settings the Kunos page lists that the catalogue does not have yet

The Kunos physics page (https://docs.assetto.cn/en/evo/car/physics/, "Car Modding Pipeline: Physics", V1, 3 June 2026) lists settings the catalogue lacks. The names below are the Kunos page's names, not proven field names: find the real names with `car_json.py decode` on one of the five cars, add each setting to `tuner/catalogue.json` with its targets (description = the official statement first, then our notes, one text without a marker; `verified` false until tested in the game), write tests with synthetic files. Work with scratch `--work` and `--mods` folders.

| Setting idea | Kunos name | Where (file) | Unit / notes |
|---|---|---|---|
| Turbo lag up / lag down | "Lag Up", "Lag Dn" per turbo in the engine's turbo list | `.engine` / `.turbo` | A filter value that maps to a time: 0.999 = 3000 ms, 0.990 = 300 ms, 0.90 = 30 ms; value = old + (new - old) * saturate(1 - filter). Not the existing `throttle_lag_up` / `throttle_lag_dn` (pedal delay). |
| Shift gas cut-off level; autoblip | "Gas Cut Off Level"; autoblip curve (X = time in ms, Y = throttle) and "Is Electronic" | `.gearbox` | Gas cut-off level = throttle during the shift; Kunos advises not setting 0 on manual gearboxes because it then acts as a flat shift assist players cannot turn off. "Is Electronic" forces the autoblip regardless of the assist settings (sequentials and DCTs). The existing `auto_cut_off_time` is the length of the cut. |
| Steer assist; force feedback multiplier | "Steer Assist"; "FF Mult" | `.car` controls | Steer assist = linearity of the steering input, 1 = linear. FF Mult adjusts the baseline FFB output. |
| Damper transition speed; bump stop shape | "Damper Transition Speed Threshold"; bump stop "Length", "Reference", "Gamma", "Damping" | `.coilover` | Transition speed in m/s: from there the fast damping rate applies. Length in m (2.5 cm = 0.025). The setup overrides only the bump stop range and force, so these four stay effective (the existing `bump_stop_*` settings are the setup values). |

Not chosen for now (so nobody asks again): hub mass (`.suspension`), CG height "Base Y" (`.car`), engine throttle map (Cervone "Throttling Factor", Gamma), launch control (Start ECU), downshift protection, auto-clutch, EDL / ESP (`.car` electronics), wing and aero gains, Performance Mode content, ERS: all advanced or car-specific; revisit if needed.
